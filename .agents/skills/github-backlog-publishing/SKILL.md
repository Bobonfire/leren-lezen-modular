# GitHub Backlog Publishing

1. Controleer expliciete publicatieapproval en Definition of Ready.
2. Zoek eerst naar een equivalente issue en voorkom duplicaten.
3. Maak of actualiseer de issue met:
   - user-storytitel;
   - Given/When/Then-description;
   - acceptance criteria;
   - agent-ready task;
   - constraints en vereist bewijs;
   - Dev Summary;
   - passende agent- en statelabels.
4. Koppel de issue aan het bedoelde Project Board wanneer toegang beschikbaar is.
5. Leg issue-URL, project, status en ontbrekende rechten vast.

Kies exact een resultaat:

- Published to GitHub
- Issue published, project board update blocked
- Not published, approval required
- Not published, GitHub access blocked

Voeg tijdens publicatie geen scope toe en zet een item niet verder in de workflow
dan readiness en handoff toestaan.
